# fin-analyzer 产品需求文档（PRD）

> 版本：v0.2 | 日期：2026.07 | 作者：Yumm-del

---

## 一、产品背景

### 1.1 痛点

普通投资者面对一只股票时，需要打开 3-5 个网站（财报、新闻、研报、社区讨论）才能拼凑出一个完整的认知。这个过程耗时、碎片化、且容易被单一信息源误导。

### 1.2 机会

大模型（LLM）能理解自然语言、能总结、能结构化输出，但有两个致命问题：**幻觉**（编数据）和**时效性**（训练数据有截止日期）。如果能用实时数据结合 LLM 分析，既解决时效性又防控幻觉，就形成了一个可用产品。

### 1.3 一句话产品定义

> 输入公司名 → 自动获取数据 + LLM 分析 → 结构化简报。一个不编数据、有来源、可检验的 AI 金融分析助手。

## 二、目标用户

### 2.1 用户画像

| 类型 | 描述 | 使用场景 |
|------|------|------|
| 初级投资者 | 有投资需求但没时间做系统研究 | 快速了解一家公司的基本情况 |
| 金融专业学生 | 需要做行业分析作业 | 获取结构化报告作为研究起点 |
| 产品好奇用户 | 想体验「AI 金融分析」这件事 | 随便输入一家公司看看效果 |

### 2.2 非目标用户

- 专业机构投资者（需要实时行情、量化数据，这不是本产品范畴）
- 完全不关心金融的用户（这是工具，不是娱乐产品）

## 三、核心功能

### 3.1 P0：单公司分析（必须做）

用户输入公司名称 → 系统自动获取数据 + LLM 分析 → 输出四模块结构化报告。

**四模块模板：**

```
一、公司概况 —— 行业、主营业务、近期大事
二、近期动态 —— 利好/利空/中性表格（含来源+时间）
三、核心风险提示 —— 分级风险（🔴高/🟡中/🟢低）+ 影响分析
四、一句话总结 —— 用普通人能懂的语言概括
```

### 3.2 P0：三层数据策略 + 分级降级

这是 v0.2 最核心的架构设计。不依赖单一数据源，而是建立一个**优先级分层的降级链路**：

```
第一层（最优）：东方财富实时行情 API
  → 获取市值、PE、ROE、营收、净利润等硬指标
  → 免费、无需 Key、国内可用
  → A 股公司精准命中

第二层（补充）：Bing 搜索引擎（cn.bing.com）
  → 搜索新闻、公告、研报等软信息
  → 纯中文自然搜索词，不加英文干扰
  → 国内可用，但中文分词质量有限

第三层（兜底）：LLM 训练知识
  → 前两层都不可用时启用
  → 报告中明确标注「基于 AI 训练知识」
  → 给出核查建议（东方财富/巨潮资讯）
```

**为什么是三层而不是两层？** 单一数据源不可靠——DuckDuckGo 被墙、Bing 中文分词差、东方财富偶然限流。任何一层都可能挂，但三层同时挂的概率极低。这是从 v0.1 的生产事故中学到的教训。

### 3.3 P0：双界面策略

| 版本 | 用户 | 入口 |
|------|------|------|
| CLI 版（fin_analyzer.py） | 技术用户、开发者 | 终端命令行 |
| Web 版（app.py, Streamlit） | 普通投资者 | 浏览器一键打开 |

同一个核心引擎，不同界面形态。Web 版额外提供：历史记录回溯、报告下载、快速模式切换。

### 3.4 P1：并行搜索

三个维度的搜索同时发起（基本面/动态/风险），不串行等待。耗时约等于最慢的那个，而非三者之和。

### 3.5 P1：垃圾结果过滤

Bing 有时返回与公司完全无关的内容（如"宁德时代"被拆成"宁德市旅游攻略"）。系统通过域名黑名单（百度知道、知乎专栏、百度百科等）过滤不相关内容。**宁可少返回结果，也不能给 LLM 喂垃圾数据。**

### 3.6 P2（下个版本）：多公司对比

输入「比亚迪 vs 宁德时代」→ 横向对比 + 差异分析。

### 3.7 P2（下个版本）：数据可视化

报告附带 PE/PB 走势图、行业对比雷达图等。

## 四、关键设计决策

### 决策 1：为什么数据源从 DuckDuckGo 变成了"东方财富 + Bing + LLM"？

**v0.1 的方案**：DuckDuckGo 免费搜索。理由：覆盖新闻/研报/社区讨论三种信息源，无需 API Key，降低门槛。

**v0.1 上线后发现**：DuckDuckGo 在国内 **100% 不可用**（不是"不稳定"，是 DNS 解析直接被墙）。产品核心链路中断。

**v0.2 的调整**：
1. 接入东方财富实时行情 API——同样是免费、无需 Key，但国内可用，且返回的是**精准财务数据**而非泛搜索
2. Bing 作为新闻信息的补充渠道——国内可用，但对中文复合名词（如"宁德时代"→"宁德市"）分词差
3. LLM 训练知识作为最终兜底——任何搜索结果被判定为垃圾时，系统不把垃圾传给 LLM，而是直接启用训练知识模式

**PM 反思**：PRD 里写的"降低用户门槛"是错的——门槛降低了，但产品根本用不了。**可用性 > 低门槛**。先保证能跑通，再优化体验。

### 决策 2：为什么让 LLM 自由分析而非用代码套模板？

- 每家公司的情况不同——比亚迪的风险在于价格战，茅台的在于政策调控。硬套模板会丢失关键洞察
- 通过 system prompt 划框（角色+约束+模板），让 LLM 在框内自由发挥，同时保证输出结构一致

### 决策 3：为什么输出 Markdown 而非 JSON 或 HTML？

- Markdown 人可读、机可解析、可以直接粘贴到飞书/腾讯文档
- JSON 对普通用户不友好，HTML 需要渲染环境
- Web 版用 Streamlit 原生渲染 Markdown，无需二次处理

### 决策 4：为什么做 Web 版而不只做 CLI？

- CLI 的目标用户是懂命令行的技术人群，范围太窄
- Web 版将用户群扩展到所有会用浏览器的人——**产品化是用界面降低认知门槛**
- Streamlit 的选型理由：Python 原生、零 HTML/CSS/JS、能复用全部 CLI 代码

## 五、防幻觉策略

大模型会自信地编造不存在的财务数据。本产品从产品层面（而非模型层面）做三层防控：

| 层级 | 措施 | 用户可感知 |
|------|------|:--:|
| 第一层 | System prompt 硬约束：「绝不编造数据」 | ❌ 用户看不到 |
| 第二层 | 每条事实必须标注来源（东方财富/搜索 URL）| ✅ 用户看到来源链接 |
| 第三层 | 数据不可用时声明「基于 AI 训练知识，建议核实」| ✅ 用户知道信息不完整 |

> 设计理念：不是让 AI「不犯错」（做不到），而是让用户「能验证」——从被动相信变成主动检验。

**v0.2 新增**：当外部数据源完全不可用时（如 API 限流 + 搜索也失败），系统进入"纯 LLM 模式"。不是让 LLM 硬着头皮分析垃圾数据，而是**明确告知 LLM 使用训练知识**，并在报告中标注。这个设计确保了：**任何输入都能产出报告，不会出现"无法完成分析"的死胡同。**

## 六、v0.1 → v0.2 演进复盘

| 阶段 | 做了什么 | 学到了什么 |
|------|---------|-----------|
| v0.1 设计 | 选 DuckDuckGo 做搜索引擎 | PRD 方案需要生产环境验证，而非理论推演 |
| v0.1 上线 | DuckDuckGo 完全不可用 | "国内网络不稳定"是低估——实际是 100% 不可用 |
| v0.2 探索 | 试了 HuggingFace/GitHub 部署，全被墙 | 技术选型要优先考虑国内网络可达性 |
| v0.2 探索 | 给 Bing 加英文提示词、改参数 | 过度优化往往适得其反——最后回归最简单的方案 |
| v0.2 探索 | 接入东方财富 API | 用 `requests` 库被识别为机器人，换 `urllib.request` 解决 |
| v0.2 定型 | 三层数据策略 + 垃圾过滤 + 双模式 prompt | 产品设计不只是选对方案，更是规划好"出错时怎么办" |

## 七、成功指标

### 7.1 产品指标

| 指标 | 定义 | v0.2 目标 |
|------|------|:--:|
| 报告生成率 | 输入公司名后能产出完整报告的比率 | ≥ 99%（三层降级保证） |
| 实时数据覆盖率 | 报告中含东方财富实时数据的比率 | ≥ 70%（A 股全覆盖，非 A 股靠搜索） |
| 幻觉发生率 | 报告中出现编造数据的比例 | ≤ 5%（prompt 约束 + 来源标注） |
| 平均响应时间 | 从输入公司名到输出报告 | ≤ 20 秒 |
| 快速模式响应时间 | 跳过搜索，只用 LLM 训练知识 | ≤ 10 秒 |

### 7.2 迭代路线

```
v0.1 ✅ ──→ v0.2 ✅ ──→ v0.3 🔜 ──→ v1.0 🎯
CLI 基础版    Web + 三层数据   多公司对比    完整产品
搜索 + LLM    历史记录 + 下载   数据可视化   永久部署 + PDF
```

## 八、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| LLM 幻觉导致错误分析 | 用户信任崩塌 | 强制来源标注 + 三层防控 + 免责声明 |
| 东方财富 API 限流 | 实时数据缺失 | 启用二层（Bing）或三层（LLM）降级 |
| 搜索在国内不可用 | 软信息缺失 | Bing 是当前最优解；长期看需付费搜索 API |
| DeepSeek 服务不稳定 | 产品完全不可用 | 下个版本增加多模型 fallback（通义千问/豆包） |
| 中文搜索分词差 | 公司搜不准 | 东方财富 API 可精准匹配公司名 + 股票代码 |
| 监管风险（AI 生成金融内容）| 合规问题 | 每份报告底部标注「不构成投资建议」 |
